title: "Remote Access"
description: "Reach your self-hosted Vibe Kanban Indie instance from another device"
---

Vibe Kanban Indie runs entirely on your own machine — there is no cloud relay
or pairing service. To use it from another device (a phone, tablet, or second
laptop), you expose the local web UI over your own network and point a browser
at it.

<Note>
Indie is single-developer and unauthenticated. Only expose it on networks you
trust — your LAN or a private mesh such as [Tailscale](https://tailscale.com).
Do not put it on the public internet without your own authentication layer in
front.
</Note>

## Choose how to reach the host

<CardGroup cols={2}>
  <Card title="Tailscale (recommended)" icon="shield-halved">
    A private mesh network. Your phone reaches the host by a stable name from
    anywhere, with HTTPS, and nothing is exposed publicly.
  </Card>
  <Card title="Same LAN" icon="wifi">
    Reach the host by its local IP address when both devices are on the same
    Wi-Fi. Simplest, but HTTP-only and local-network-only.
  </Card>
</CardGroup>

## Bind the server to your network

By default the backend binds to `127.0.0.1`, which is only reachable from the
host itself. Set `HOST` so other devices can connect, then declare the hostname
you'll browse to with `VK_ALLOWED_HOSTS` and the origin with
`VK_ALLOWED_ORIGINS`.

<Warning>
**Reaching the board by IP address needs no `Host` configuration.** The server
answers requests addressed to `localhost` or to any IP literal — so
`http://192.168.1.50:3000` or a Tailscale `http://100.101.102.103:3000` work
with `HOST` alone. What it rejects is an unrecognised **hostname**, because a
DNS-rebinding attack always arrives as a name: a public website resolves its own
hostname to your machine's address and then drives your unauthenticated board
from your browser. A browser can never be made to send an IP-literal `Host` for
someone else's origin, which is why the exemption is safe.

So a name — a Tailscale MagicDNS name, `host.local`, a reverse-proxy domain —
needs that name in `VK_ALLOWED_HOSTS`, and its origin in `VK_ALLOWED_ORIGINS`.
</Warning>

<Steps>
<Step title="Bind to all interfaces">
  Start the app with `HOST` set so it listens on every interface:

  ```bash
  HOST=0.0.0.0 npx vibe-kanban-indie
  ```

  <Warning>
  On Windows, also set `MCP_HOST=127.0.0.1` so the MCP server still connects
  locally when `HOST=0.0.0.0`.
  </Warning>
</Step>

<Step title="Allow the hostname you browse to">
  Skip this step if you browse to an IP address — that already works. If you
  type a **name** into the address bar, the request is rejected with `403
  Forbidden` and a body explaining why until you list it:

  ```bash
  VK_ALLOWED_HOSTS="host.your-tailnet.ts.net,192.168.1.50:3000" \
    HOST=0.0.0.0 npx vibe-kanban-indie
  ```

  Entries are comma-separated. Each one is a bare authority (`app:3000`) or a
  full URL whose authority is used (`https://host.your-tailnet.ts.net`), so you
  can paste the same values you use for `VK_ALLOWED_ORIGINS`. **An entry with no
  port matches that host on any port**; an entry with a port matches only that
  port. Port pinning only means anything for names — an IP literal is accepted
  on every port regardless, so listing one has no effect.

  <Note>
  `VK_ALLOWED_HOSTS=*` accepts any `Host` header, which switches the guard off.
  Only do this behind a proxy that already restricts who can reach the server —
  it re-opens the DNS-rebinding hole for anyone who can point a hostname at your
  machine.
  </Note>
</Step>

<Step title="Allow your browsing origin">
  When you access the UI by any host other than `localhost`, the browser's
  `Origin` header won't match either, and requests are rejected with `403
  Forbidden`. List the origins you'll use:

  ```bash
  VK_ALLOWED_HOSTS="host.your-tailnet.ts.net,192.168.1.50:3000" \
    VK_ALLOWED_ORIGINS="https://host.your-tailnet.ts.net,http://192.168.1.50:3000" \
    HOST=0.0.0.0 npx vibe-kanban-indie
  ```

  Unlike `VK_ALLOWED_ORIGINS`, which is also editable at runtime under
  **Settings → Network**, `VK_ALLOWED_HOSTS` is read once at start-up and needs
  a restart to change. It has to be: a rejected `Host` returns 403 for *every*
  route, the Settings page included, so a UI knob could not be used to recover.

  <Check>
  Open the URL on your other device. The board should load and stay
  connected.
  </Check>
</Step>
</Steps>

## Add HTTPS with a reverse proxy

For a stable name and HTTPS (required for some browser features on mobile), put
a reverse proxy in front. The repository ships a
[`Caddyfile.example`](https://github.com/dexloom/vibe-kanban-indie/blob/main/Caddyfile.example)
and a full [mobile testing walkthrough](https://github.com/dexloom/vibe-kanban-indie/blob/main/mobile-testing.md)
that combines **Tailscale** (stable networking + certificates) with **Caddy**
(reverse proxy) so you can reach the UI from a phone on any network in about
fifteen minutes.

Other tunnels such as Cloudflare Tunnel or ngrok work the same way: expose the
web UI, then add the tunnel hostname to `VK_ALLOWED_HOSTS` and the tunnel URL to
`VK_ALLOWED_ORIGINS`.

<Tip>
A reverse proxy can satisfy the `Host` guard on its own. Configure it to rewrite
the upstream `Host` to the loopback address it dials — in Caddy,
`reverse_proxy 127.0.0.1:3000 { header_up Host {upstream_hostport} }` — and the
backend sees `127.0.0.1:3000` and needs no `VK_ALLOWED_HOSTS` entry. Proxies
that forward the public `Host` unchanged (Caddy's default) do need the public
name listed. A proxy that dials the app by a container name (Traefik to
`http://app:3000`) sends `Host: app:3000`, a name, so it needs
`VK_ALLOWED_HOSTS="app:3000"` too.
</Tip>

<Note>
**Why the app checks this rather than your proxy.** The proxy sits between the
internet and the app — not between a local browser and the app. A rebound
request comes from JavaScript in a developer's own browser, inside the network,
straight to the app's port, so it never traverses the edge and the edge cannot
filter it. The guard also covers the setups with no edge at all: `npx
vibe-kanban-indie`, `pnpm run dev`, the desktop app, and `vibe-tui`. Full
reasoning in
[`docs/ADR/ADR-025-loopback-host-guard.md`](https://github.com/dexloom/vibe-kanban-indie/blob/main/docs/ADR/ADR-025-loopback-host-guard.md).
</Note>

## Open your editor on the remote host

When the app runs on a remote server, the "Open in VSCode" buttons can connect
your local editor over SSH instead of assuming `localhost`. Configure this in
**Settings → Editor Integration**; see [General Settings](/settings/general)
for details.
