title: "Orchestrator"
description: "A singleton headed agent session that dispatches ready cards to coding agents"
---

The orchestrator is a single, long-lived **headed Claude Code** session that
drives the board on your behalf. On a recurring loop it finds cards that are ready
to run, picks which coding agent to start for each, starts it through the Vibe
Kanban MCP tools, and keeps each managed card's board column in sync with what its
coding agent has actually accomplished. It does not drive, review, or merge the
work itself — once a card is dispatched, the coding agent owns execution end to
end; the orchestrator only dispatches and reflects status.

## What makes it special

- **Singleton.** There is at most one active orchestrator at a time. Requesting a
  new one reuses the existing session rather than spawning a second.
- **Repo-independent.** It does not belong to any one project. It runs from a
  fixed `~/.vibe-kanban/orchestrator` folder, so it can reason across every
  project on the board.
- **Headed.** It runs as an interactive Claude Code session (a detached tmux
  session), so you can attach to it, watch it think, and send it input — the same
  controls as any headed workspace.

## Spawning it

Spawn the orchestrator from the app. Spawning is **idempotent**: if an
orchestrator is already running, the action returns the existing session instead
of creating a new one. The app launches it as the plugin's own session agent
(`claude --agent vibe-kanban-indie:orchestrator`) on a `/loop` timer. Each tick
runs in one of two modes: a cheap **monitor** pass over the currently active cards
(the default), or a full board **sweep** (find ready cards, dispatch one coding
agent per card) that runs only when a dispatch trigger fires — nothing is active,
a card just shipped, an operator instruction asks for it, or a periodic backstop
is due. The agent adapts its own cadence, backing off from 5 minutes to 30 when
the board goes idle and snapping back when work returns.

<Note>
The orchestrator's full behaviour lives in the plugin's agent definition
(`agents/orchestrator.md` in the `vibe-kanban-indie` plugin). The `/loop` body the
app composes is only a short per-tick pointer — the same one the plugin's own
launcher uses — so the behaviour survives context compaction over a days-long run.
</Note>

<Note>
Because it runs from `~/.vibe-kanban/orchestrator` rather than a project worktree,
the orchestrator has no working repository of its own. It acts on projects by
calling MCP tools, not by editing files directly.
</Note>

## How it acts on the board

The orchestrator uses the Vibe Kanban MCP server in **global** mode, which gives
it board-wide tools to:

- List and read issues, repositories, and workspaces (to find ready cards and avoid
  starting one that already has a workspace)
- Resolve which coding agent to run — the agent pinned in the card's pipeline, or
  your last-used/default agent configuration when the card pins none
- Start a workspace and dispatch one coding agent per ready card, then move the card
  to In Progress
- Reflect each managed card's status back onto the board — In Review when the
  pipeline is complete but nothing landed, Done when the merge or PR has actually
  landed — and hold and surface cards parked at an operator-approval gate

Approvals, reviews, merges, and answering an agent's questions stay outside the
orchestrator's default scope: the coding agent drives its own pipeline, and you make
the decisions.

## Per-project and per-board prompts

You can give the orchestrator **scoped instructions** that apply only when it works a
card in a particular project or board — a project-level baseline, refined further per
board. Prompts are plain text you edit in the app, and they apply **live**: the
orchestrator re-reads the resolved prompt on every tick, so editing never requires
restarting its session.

- **Edit from the sidebar.** A project row's **+** menu offers **Add orchestrator
  prompt**, which opens a full-page editor with a textarea, an explicit **Save**, and
  a **Clear** (writes an empty prompt). Once a prompt is saved, an **Orchestrator
  prompt** node appears under that project or board in the tree, with a dot that
  marks a prompt is set there.
- **Stack resolution.** The orchestrator receives **every** non-empty prompt in the
  parent chain, ordered most-specific first: the board's prompt, then the project
  baseline. Where sections agree they stack additively; on a direct conflict the more
  specific (board) section wins. Clearing a board's prompt falls back to the project
  baseline.
- **Inheritance badges.** When a board's own prompt is empty, the editor shows
  *Inherited from an ancestor project* (if a parent sets one) or *Using default
  behaviour* (if nothing in the chain does). `source: "default"` means the
  orchestrator uses its built-in behaviour for that card.

<Tip>
Because resolution walks the chain each tick, you can set a broad baseline on the
root project and tighten it per board without duplicating the baseline into each
board's prompt.
</Tip>

When you spawn the orchestrator you can opt into **directives** — extra behaviours it
applies on each tick:

- **Auto-unblock approvals** — auto-approve routine, plan-sanctioned tool requests;
  escalate destructive or off-plan ones to you.
- **Auto-answer questions** — once an agent's question has gone unanswered past a grace
  window, a `decider` subagent reads the card, spec, and plan and answers it for you.
- **Telegram fan-out** — narrate status and converse with each agent over its
  per-workspace Telegram topic (requires the Telegram bridge).
- **Nudge stuck agents** — send "Why are you stuck" to a managed agent that shows no
  progress for two consecutive ticks.

These are emitted as simple flags in a "Directives enabled for this run" block at
the end of the spawn prompt; the orchestrator's plugin instructions define what each
flag does.

## Staying in control

You remain the final authority. At any time you can:

- Attach to the orchestrator's tmux session to watch or steer it
- Override any decision from the [TUI cockpit](/cockpit/tui)
- Reply directly in Telegram
