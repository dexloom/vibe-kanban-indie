title: "Deploy with Docker"
description: "Run Vibe Kanban Indie on your own server with Docker"
---

Vibe Kanban Indie ships a `Dockerfile` that builds a single, self-contained
image: the Rust backend serving the prebuilt web UI on port `3000`. There is no
database server, OAuth provider, or relay to run — state lives in a SQLite
database inside the container, which you persist with a volume.

<Note>
Indie is single-developer and unauthenticated. Treat the container as private:
keep it on a trusted network and put your own authentication in front before
exposing it publicly. See [Remote Access](/remote-access).
</Note>

## Prerequisites

- **Docker** installed on the host
- **Git** to clone the repository

## Step 1: Build the image

```bash
git clone https://github.com/dexloom/vibe-kanban-indie.git
cd vibe-kanban-indie
docker build -t vibe-kanban-indie .
```

## Step 2: Run the container

The image listens on port `3000` and runs the server as an unprivileged user.
Mount a named volume so your projects, issues, and settings survive restarts:

```bash
docker run -d \
  --name vibe-kanban-indie \
  -p 3000:3000 \
  -e VK_ALLOWED_ORIGINS="http://localhost:3000" \
  -v vk-data:/home/appuser/.local/share/vibe-kanban \
  -v vk-config:/home/appuser/.config/vibe-kanban \
  vibe-kanban-indie
```

<Check>
Open `http://localhost:3000`. The board loads and the container reports healthy
(`docker ps` shows `healthy` once the start-up check passes).
</Check>

## Configuration

Pass configuration as environment variables with `-e`:

| Variable | Purpose |
|---|---|
| `PORT` | Port the server listens on inside the container (default `3000`) |
| `HOST` | Bind address (default `0.0.0.0` in the image) |
| `VK_ALLOWED_HOSTS` | Comma-separated hostnames the server will answer to, on top of loopback. Required when you reach the UI by any host other than `localhost`, otherwise requests are rejected with `403 Forbidden` |
| `VK_ALLOWED_ORIGINS` | Comma-separated origins allowed to call the API. Required when you access the UI by any host other than `localhost`, otherwise requests are rejected with `403 Forbidden` |

<Warning>
When you reach the container through a reverse proxy or a different hostname,
set **both**: add the hostname (and port, if you browse to a non-default one) to
`VK_ALLOWED_HOSTS`, and the exact origin (scheme, host, and port) to
`VK_ALLOWED_ORIGINS` — e.g. `VK_ALLOWED_HOSTS="vk.example.com"` with
`VK_ALLOWED_ORIGINS="https://vk.example.com"`.

The `Host` check is the DNS-rebinding defence: without it, a public website
could resolve its own hostname to your container's address and drive the
unauthenticated API from a visitor's browser. `VK_ALLOWED_HOSTS=*` disables it
entirely and is only sensible behind a proxy that already controls who can
connect. It is read once at start-up, so changing it needs a container restart.
</Warning>

## Working with repositories

The app operates on Git repositories. Mount the repositories you want to manage
into the container and add them as projects in `projects.toml`:

```bash
docker run -d \
  --name vibe-kanban-indie \
  -p 3000:3000 \
  -v vk-data:/home/appuser/.local/share/vibe-kanban \
  -v vk-config:/home/appuser/.config/vibe-kanban \
  -v /srv/code:/repos \
  vibe-kanban-indie
```

## Updating

Rebuild the image from the latest source and recreate the container; your data
volume is preserved:

```bash
git pull
docker build -t vibe-kanban-indie .
docker rm -f vibe-kanban-indie
# re-run the docker run command from Step 2
```

## Reverse proxy and HTTPS

To serve the app over HTTPS on a domain, put a reverse proxy such as Caddy in
front. The repository includes a
[`Caddyfile.example`](https://github.com/dexloom/vibe-kanban-indie/blob/main/Caddyfile.example)
to start from. Remember to add the public origin to `VK_ALLOWED_ORIGINS`, and
the public hostname to `VK_ALLOWED_HOSTS` — unless the proxy rewrites the
upstream `Host` to loopback, e.g.
`reverse_proxy 127.0.0.1:3000 { header_up Host {upstream_hostport} }`, in which
case the backend already sees a loopback `Host`.
