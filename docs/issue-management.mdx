Issues are the fundamental unit of work in Vibe Kanban. Each represents a bug,
feature, or piece of work — and an issue's description becomes the prompt your
coding agent receives when you create a workspace. This guide covers the full
issue lifecycle.

## What an issue holds

| Property | Description |
|----------|-------------|
| **Title** | A short description of what needs to be done |
| **Description** | Detailed context, requirements, and instructions |
| **Status** | Which column it's in (Todo, In Progress, In Review, Done) |
| **Priority** | How urgent it is (Urgent, High, Medium, Low) |
| **Tags** | Labels for categorisation and filtering |
| **Simple ID** | A unique identifier like `ACME-123` for easy reference |

## 1. Create an issue

Create an issue from the **+** button on any column header (it opens pre-set to
that status), or from the **New Issue** button in the filter bar.

<Frame>
  <img src="/images/issue-mgmt-create-button.png" alt="Kanban board showing the New Issue button in the header and the plus button on a column" />
</Frame>

<Steps>
<Step title="Enter a title">
  Type a clear, specific title that describes the outcome you want. The title
  field is focused automatically.
</Step>
<Step title="Set the status">
  Choose which column the issue starts in.
</Step>
<Step title="Set priority and tags (optional)">
  Set a priority and add tags to categorise it.
</Step>
<Step title="Add a description (optional)">
  Write detailed instructions using the rich text editor (see below).
</Step>
<Step title="Create">
  The issue appears on the board in the selected column.
</Step>
</Steps>

<Tip>
To start work immediately, enable **Create draft workspace immediately** when
creating the issue. It's created with a linked [workspace](/workspaces/index) so
you can dispatch a coding agent right away. You can also expand a brief into a
full task first — see [Generate a Spec](/cockpit/spec-intake).
</Tip>

## 2. Write an effective description

The description is where you give your coding agent context. Use the rich text
editor to format instructions with bold, italic, lists, and inline code, plus
markdown shortcuts for headings (`#`) and links (`[text](url)`).

<Frame>
  <img style={{maxHeight: "300px"}} src="/images/issue-mgmt-description.png" alt="Issue description editor with formatted text including headings and code blocks" />
</Frame>

A good description is the difference between an agent that delivers what you need
and one that goes off track.

| Element | Weak example | Strong example |
|---------|-------------|----------------|
| **Title** | "Fix bug" | "Fix login timeout on slow connections" |
| **Description** | "It's broken" | "Users on 3G see a timeout after 5 s. Expected: graceful retry with exponential backoff." |

<Tip>
Your issue description becomes the prompt your coding agent receives. The more
specific you are, the better the result.
</Tip>

## 3. Set priority and tags

| Priority | When to use |
|----------|-------------|
| **Urgent** | Production is down or work is blocked |
| **High** | Important work that should be picked up next |
| **Medium** | Standard work |
| **Low** | Nice-to-have improvements or future ideas |

<Info>
Tags are project-specific and created inline from the tag selector. See
[Customising your board](/board/customisation#managing-tags).
</Info>

## 4. Edit issues

Click any card to open the issue panel on the right.

- **Title and description** save **automatically** a moment after you stop typing.
- **Status, priority, and tags** save **immediately** when you change
  them — or change status by dragging the card to another column.

## 5. Issue sections

The issue panel has collapsible sections for related work:

- **Workspaces** — development [workspaces](/workspaces/index) linked to this
  issue, where coding agents do the work. Use the **+** to create a new workspace
  or link an existing one; you can link several to run agents in parallel.
- **Sub-Issues** — child issues for breaking work down (see below).
- **Comments** — a discussion thread for the issue, with emoji reactions.

<Frame>
  <img style={{maxHeight: "300px"}} src="/images/issue-mgmt-link-workspace.png" alt="Issue panel showing the Workspaces section with Create and link buttons" />
</Frame>

## 6. Break work down with sub-issues

Large features are easier to manage when split into smaller, agent-sized tasks.
Open the parent issue, expand the **Sub-Issues** section, and either create a new
child issue or link an existing one.

<Frame>
  <img style={{maxHeight: "300px"}} src="/images/issue-mgmt-sub-issues.png" alt="Sub-issues section showing child issues with mixed statuses" />
</Frame>

- Each sub-issue has its **own independent status** — completing all children does
  not auto-complete the parent.
- A sub-issue shows a **Parent** link to navigate back.
- Sub-issues are one level deep — a sub-issue can't have its own sub-issues.

## 7. Issue actions and the command bar

Quick actions are available from the **More** (⋯) button in the issue panel, or
from the **command bar** — press `Cmd/Ctrl + K` and choose **Issue Actions**.

<Frame>
  <img style={{maxHeight: "350px"}} src="/images/cloud/command-panel-issue-actions.png" alt="Command panel showing Issue Actions option" />
</Frame>

Available actions include: change status, change priority, make
this a sub-issue of another, add a sub-issue, link a workspace, duplicate the
issue, and delete the issue.

## Selecting multiple issues

Select several issues to act on them together, in both the
[kanban board](/board/kanban) and [list view](/board/list-view):

| Method | Action |
|--------|--------|
| **Cmd/Ctrl + Click** | Toggle an issue in or out of the selection |
| **Shift + Click** | Select a range from the last selected issue |
| **Cmd/Ctrl + A** | Select all visible issues |
| **Checkbox** (list view) | Hover the left edge of a row to reveal its checkbox |
| **Escape** | Clear the selection |

When two or more issues are selected, a **bulk action bar** appears at the bottom
of the screen. From it you can change the **status** or **priority** of every
selected issue at once, or **delete** them.

<Warning>
Bulk delete is permanent and cannot be undone.
</Warning>

## Simple IDs

Every issue has a **Simple ID** — a short identifier like `ACME-123`, built from
the project key. It appears on cards, in the panel header, and in the issue URL.

<Tip>
Use Simple IDs in commit messages (e.g. "Fix login bug ACME-123") to tie code to
issues.
</Tip>

## Deleting issues

Delete a single issue from the **More** (⋯) menu → **Delete Issue**, or delete
several at once with the bulk action bar.

<Warning>
Deleting an issue is permanent — the issue, its comments, and its history are
removed. Sub-issues are not deleted; they become standalone issues.
</Warning>

## Troubleshooting

<AccordionGroup>
<Accordion title="Issue doesn't appear on the board">
- Check your active filters — click **Clear All** to reset them.
- The issue may be in a **hidden status** — open [list view](/board/list-view) to
  see issues in hidden statuses.
</Accordion>

<Accordion title="Can't drag issues to reorder them">
Sort mode must be set to **Manual**. If sorting is set to Priority, Created,
Updated, or Title, drag-to-reorder is disabled. Change the sort option in the
board header.
</Accordion>

<Accordion title="Description changes aren't saving">
Title and description auto-save a moment after you stop typing. If you close the
panel immediately, wait a beat for the save to complete.
</Accordion>
</AccordionGroup>
