---

Vibe Kanban Indie is an open-source, self-hosted project. It runs entirely on
your own machine and ships no hosted service. Even so, we welcome responsible
reports of security vulnerabilities so issues can be identified and fixed
quickly.

## How to report a security issue

Report vulnerabilities privately through GitHub Security Advisories, **not** in
a public issue:

1. Open the repository at
   [github.com/dexloom/vibe-kanban-indie](https://github.com/dexloom/vibe-kanban-indie).
2. Go to the **Security** tab and choose **Report a vulnerability**.
3. Submit a private advisory with the details below.

<Warning>
Please do not open a public GitHub issue, pull request, or discussion for a
security vulnerability before it has been fixed and a release is available.
</Warning>

When submitting a report, include where possible:

- **Summary** of the vulnerability and its potential impact
- **Steps to reproduce** the issue (screenshots or clear descriptions help)
- **Environment details** (OS, version, how you run the app)
- **Proof-of-concept code** or relevant exploit details

Upon receipt, we will:

1. Acknowledge the report.
2. Investigate and triage the issue.
3. Follow up for clarification or retesting if needed.
4. Work to remediate the issue and publish a fix.

## What's in scope

The code in this repository — the local server, web UI, CLI, MCP server, TUI,
and Telegram bridge — is in scope. Because Indie is self-hosted with no central
service, the most relevant classes of issue are:

- Arbitrary code execution reachable from the web UI or API
- Path traversal or arbitrary file read/write outside the workspace
- Authentication or origin-check bypasses (for example `VK_ALLOWED_ORIGINS`)
- Injection that leads to host compromise

If you are unsure whether something is in scope, ask in a private advisory
before testing.

## What's out of scope

- Issues that require already having local/physical access to the host
- Findings in upstream dependencies (report those to the relevant project)
- Automated scanning output without a demonstrated, practical impact
- Rate-limiting or missing-header reports with no material harm
- Denial-of-service against an instance you control
- Theoretical vulnerabilities without a practical proof of exploitability

## Please do not

- Access or modify data that does not belong to you
- Test against instances you do not own or operate
- Share details of an unfixed issue publicly

## Recognition

This is a volunteer-maintained fork, so there is no bug-bounty programme.
Researchers who report valid, clearly documented issues in good faith will be
credited in the release notes and security advisory unless they prefer to
remain anonymous.
